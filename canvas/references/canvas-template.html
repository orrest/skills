Visual mode template

Process visualization template

This example shows the default structure and inline style for process-oriented visual mode outputs.

Header banner: title and one-line description
Main sequence: the process flow
Supporting details: parameters, conditions, and hidden information
Object map: related objects and their goals

Main sequence

1

Receive input

The process starts when a request, file, event, or command enters the system.

validate and classify
2

Decide the route

Rules, conditions, or feature flags decide whether the flow continues normally or branches.

Parameter note

Use notes for IDs, flags, file paths, thresholds, or inputs that influence later decisions.

run the main action
3

Execute the core step

The primary action runs only after the setup and branch checks are complete.

4

Produce the result

The process finishes by creating an output, updating state, or handing off to the next owner.

Supporting details

Parameters

Use this area for inputs such as path, mode, or identifiers that shape the flow.

Conditions and branches

Call out early exits, optional paths, validation gates, or branch-specific behavior that should not be buried in the main sequence.

Hidden information

Use this section for side effects, cleanup, background work, assumptions, or lifecycle details that matter but are easy to miss.

Object map

Input object

Request

Goal: carry the data that starts the process and provides routing context.

Control object

Coordinator

Goal: own the sequence and decide which branch or action runs next.

Work object

Worker

Goal: perform the core operation that advances the process.

Output object

Result

Goal: capture the finished state, visible outcome, or handoff artifact.
